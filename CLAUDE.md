## Architecture

### Feature Structure

Each feature under `lib/pages/<feature>/` follows:
```
<feature>/
  api/          ← Dio HTTP calls, returns raw models
  bloc/         ← BLoC event/state files (or cubit/)
  model/        ← @JsonSerializable models + generated .g.dart files
  screen/       ← StatelessWidget/StatefulWidget UI files
```

### State Management

Two patterns coexist — **do not mix them within the same feature**:

1. **BLoC** (`flutter_bloc`): Used in the Tasks feature. Events extend `TasksEvent`, states use `@freezed` with `copyWith`. The state file has a `.freezed.dart` counterpart generated by build_runner.

2. **Cubit** via `BaseCubit<TState>` (`lib/core/constants/base_cubit.dart`): Provides `executeApi()` helper that wraps loading/success/error transitions using `ApiResult<T>`.

Generic state lifecycle uses `BaseState` (`lib/core/constants/base_state.dart`): `InitialState`, `LoadingState`, `SuccessState<T>`, `ErrorState`.

### Networking Layer

- **`DioFactory`** (`lib/core/networking/dio_factory.dart`): Singleton Dio instance. Call `DioFactory.setTokenIntoHeaderAfterLogin(token)` after login to attach the Bearer token.
- **`BaseApi`** (`lib/core/constants/base_api.dart`): Abstract class with `execute<T>()` helper. Catches `DioException` and wraps it in `ApiResult.failure(ErrorModel)`.
- **`ApiResult<T>`** (`lib/core/networking/api_result.dart`): Freezed union — `ApiResult.success(data)` / `ApiResult.failure(error)`. Use `.when(success:, failure:)` to handle.
- **`ErrorHandler`** (`lib/core/networking/api_error_handler.dart`): Maps `DioExceptionType` to `ErrorModel`. Used internally by `BaseApi`.
- **`ApiConstants`** (`lib/core/networking/api_constans.dart`): All endpoint paths and base URL.

**Important**: There are two `ErrorModel` classes:
- `lib/core/constants/model/error_model.dart` — has `message` + `errors: Map<String, List<String>>`. Used by `BaseApi` and `ApiResult`.
- `lib/core/networking/api_error_model.dart` — has `message` + `code`. Used by `ErrorHandler` internally.

Always import the `constants/model/error_model.dart` version for API responses.

### Session & Authentication

`UserSession` (`lib/core/constants/functions.dart`) is a static in-memory session backed by `UserPreferencesService` (SharedPreferences). Call `UserSession.init()` at app startup to restore the session.

Key members:
- `UserSession.token` — current Bearer token (nullable)
- `UserSession.isLoggedIn` — bool
- `UserSession.user` — `UserModel?`
- `UserSession.updateSession(SigninResponseModel)` — saves full session after login
- `UserSession.clear()` — logout

Auth models live in `lib/pages/auth/sign_in/model/`. The response envelope is `SigninResponseModel { succeeded, data: SigninModel, error: ErrorModel }`.

### Navigation

GetX routing via `Map<String, WidgetBuilder>` in `lib/routes.dart`. Each screen exposes a `static String id = "/route-name"`.

Use `Get.toNamed(ScreenName.id)` to navigate, `Get.offAllNamed(ScreenName.id)` to clear the stack.

### Theme & Design System

- **Theme**: `lib/core/constants/theme.dart` exports `lightTheme` / `darkTheme`. Wrapped with `AdaptiveTheme` in `main.dart`.
- **Colors**: `lib/core/constants/colors.dart` — `AppColors` class. `AppColor` is a typedef alias for backward compatibility.
- **Font**: Cairo (local). Font family name in pubspec and `TextStyle` is `'Cairo-Bold'`. Files: `assets/fonts/cairo/Cairo-Regular.ttf`, `Cairo-Bold.ttf`.
- **Responsive sizing**: `flutter_screenutil` initialized with design size `392×825`. Use `.w`, `.h`, `.sp`, `.r` extensions.

### Shared Components (`lib/core/components/`)

| Component | Purpose |
|-----------|---------|
| `AppText` | Text widget with Cairo font defaults. Accepts `style` override. |
| `AppButton` | Gradient button with loading state, consistent height/radius. |
| `AppTextFormField` | Styled form field with validation support. |
| `CustomAppBar` | `PreferredSizeWidget` AppBar with optional `TabBar`. |

| `AppDrawer` | Sidebar drawer with logout action. |
| `AppAnimation` | Scale-press animation wrapper. |

### Code Generation

Any file annotated with `@freezed` or `@JsonSerializable` generates a `.freezed.dart` or `.g.dart` file. **Never edit generated files.** Re-run build_runner after changes.

### Key Known Issues / In-Progress Areas

- `UserSession` and `UserPreferencesService` in `functions.dart` replace the commented-out versions in `cached/user_session.dart` (which still references an old `AccountModel`).
- `lib/core/signalr/signalr_service.dart` is a stub — `signalr_netcore` is not in pubspec. Backend integration pending.
- `lib/core/di/dependency_injection.dart` is minimal — the project currently creates API instances directly in BLoCs (e.g., `TasksBloc` instantiates `TasksApi` inline). DI expansion is planned.
- `lib/pages/home/screen/sign_in.dart` and `lib/pages/auth/sign_in/screen/sign_in.dart` are empty stubs — the real implementation is `sign_in_screen.dart`.

### Localization

GetX `.tr` extension is used on UI strings throughout. A translation file must be created at `lib/core/localization/translation.dart` and registered as `translations: AppTranslations()` in `GetMaterialApp` (currently removed from `main.dart`). The app locale is `Locale("ar")` for Arabic / RTL.
